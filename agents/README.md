# Canonical agent contracts — design only

These six YAML files represent the canonical executive agents in the current [Reference Architecture v1.2](../REVIEWER_GUIDE.md). They were originally transcribed from v1.1; the editorial document revision does not change these interface shapes. Each accepts an `AgentRequest` with `treasury_state`, `objective`, `constraints` and `context`, and returns an `AgentResponse` with `observation`, `reasoning_summary`, `proposed_action`, `expected_effect`, `confidence`, `required_controls` and `evidence`. `proposed_action` may be absent when the agent cannot support an action from available information.

The response is **non-executable**. An agent cannot set `execute=true`, issue an `AuthorizedInstruction`, approve itself, or bypass the deterministic Control Plane within the Governance and Authority Plane. The Governance Agent interprets control implications; it is separate from the Control Plane. The optional Orchestrator is not a seventh authority-bearing agent.

These are proposed interface contracts. Phase A used fixed Proposed Actions and did not test agent competence, coordination, forecasts, model outputs, or these YAML files. [Phase B v1.3](../phase-b/README.md) now archives its own model identity, prompts, parameters, raw responses, parsed outputs and errors as D03. Its eight cases each use four sequential calls to the same model. The executed output contract is [`contracts.py`](../phase-b/v1.3/ata-phase-b/contracts.py); the prompts and call plan are in [`phase_b.py`](../phase-b/v1.3/ata-phase-b/phase_b.py). D03 does not demonstrate conformance to these six YAML interfaces, their superiority, or independent predictive capability.
